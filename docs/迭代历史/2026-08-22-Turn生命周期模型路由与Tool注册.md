# 2026-08-22：Turn 生命周期、模型路由与 Tool 注册

## 背景

代码复盘发现三个可扩展性问题：`turn_start` 位于 AgentLoop 内导致模型重试时重复发布；所有 Agent 共用 YAML 中的单一模型连接；三个内置 Tool 集中在一个类中且由 `ToolExecutor` 直接注册。

## 本次变更

- 新增 `AgentTurnPreparer`，在选择执行器和进入 Attempt 前统一重建历史、追加当前用户消息并发布一次 `turn_start`。
- LOOP 与 WORKFLOW 执行器接收同一份 Turn 消息基线，每个 Attempt 使用独立副本。
- 新增 `model_provider_config`，保存供应商 key、协议、Base URL、API Key、状态和可选用户归属。
- `agent_config` 增加供应商 key、模型名和 temperature；旧数据自动绑定默认 DeepSeek 配置。
- 默认模型统一调整为 `deepseek-v4-flash`；数据库 Agent 配置优先，YAML 只保留兜底值。
- 新增 `ModelRegistry`，按供应商连接缓存 OpenAI 兼容客户端，每次调用应用 Agent 级模型参数。
- API Key 支持数据库原值和 `env:变量名`，`/api/agents` 使用脱敏 DTO，不返回密钥。
- 新增 `/api/models` 模型目录接口，按系统供应商或当前用户私有供应商过滤，只返回模型元信息、可用状态和不可用原因。
- `conversation` 增加供应商和模型字段；前端将 Agent 与模型作为两个独立选择项，同一会话可从下一 Turn 切换模型，刷新或切换会话时恢复最后选择。
- 内置目录增加 Zhipu GLM、proaiapi 和呆呆兽中转站。CC Switch 的真实 API Key 仅导入本机 MySQL，仓库中的幂等种子使用环境变量引用，不保存凭据。
- CC Switch 三项配置使用 `OPENAI_RESPONSES`。Spring AI 1.1.7 当前模型链只支持 Chat Completions，因此目录接口将它们标记为不可用，待独立 Responses 适配器完成后再开放选择。
- Tool 定义拆入 `agent.tool.definition`：`TimeTools`、`CalculateTools`、`ConversationTools`。
- 新增 `AgentToolProvider` 与 `ToolRegistry`，通过 Spring IoC 自动发现并注册 Tool；重复名称启动失败。
- `ToolExecutor` 保留工具白名单、上下文注入、异常包装和事件发布职责，不再依赖具体 Tool 类。

## 用户私有模型配置预留

- `model_provider_config.user_id = NULL` 表示系统供应商，非空表示未来的用户私有供应商。
- 当前全局 Agent 配方引用系统供应商；未来可在用户级 Agent 或会话覆盖层引用用户自己的供应商。
- 正式开放用户录入 API Key 前，必须增加服务端加密存储、用户所有权校验、密钥更新脱敏和删除清理策略。
