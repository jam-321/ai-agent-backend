# 可读性与管理员监控

> 日期：2026-08-16

## 背景

AgentLoop 初版已经可以运行，但核心 Java 类、仓储 SQL 和恢复流程压缩在少量长行中，不利于学习和排查。下一阶段还需要一个管理员入口观察会话、Turn、Node 和工具执行数据，配合 DBeaver 做数据库级调试。

## 本次改动

### AgentLoop 可读性

- 将 Model、Outer Attempt、Inner Loop、Tool Executor、Event Publisher、Turn Finalizer 和异步 Worker 的职责边界展开。
- 为重试边界、工具异常回注、会话锁生命周期、重启补偿、历史消息重建和终态落库补充面向不变量的注释。
- 持久化层从 `JdbcTemplate` 迁移到 MyBatis-Plus 3.5.12：表结构由 Entity 映射，简单 CRUD 使用 `BaseMapper`，复杂查询集中到 Mapper XML。
- Repository 不再拼 SQL 或处理 `ResultSet`，只负责 Mapper 调用、用户隔离结果和领域 record 转换。
- `conversation_node` 插入后由 MyBatis-Plus 将当前 INSERT 的自增主键回填到 Entity。多工具并行执行时不会通过查询某个 Turn 的最新 ID 猜测刚插入的行。
- 管理员启动迁移、Turn 终态去重检查和监控统计也已迁移到 Mapper，不保留 JDBC 直接调用。

### 管理员身份

- `app_user.is_admin TINYINT NOT NULL DEFAULT 0`：注册用户默认为普通用户。
- `AuthenticatedUser`、`UserResponse`、Session 属性和 Security authority 均携带管理员标记。
- `/api/admin/**` 要求 `ROLE_ADMIN`；管理员没有独立的会话或聊天入口，仍然使用普通会话接口。
- 已有数据库由 `DatabaseSchemaMigration` 检查 `information_schema.columns`，缺列时执行一次 `ALTER TABLE`。新库仍由 `schema.sql` 直接建列。
- 提升账号可在 DBeaver 执行：

  ```sql
  UPDATE app_user SET is_admin = 1 WHERE username = '你的用户名';
  ```

  提升后退出并重新登录，让新的管理员标记进入 Redis Session。

### 管理监控

- `GET /api/admin/monitor/overview`：用户、会话、Turn、Node、运行终态和工具调用汇总。
- `GET /api/admin/monitor/conversations`：按用户名/标题搜索的分页会话列表，附 Turn 数、Node 数和最新状态。
- `GET /api/admin/monitor/conversations/{id}`：单会话完整 Turn 记录和 Node 时间线，便于检查短期记忆重建素材。
- `GET /api/admin/monitor/tools`：工具调用成功/失败/执行中数量和平均耗时。
- 前端监控页只在 `currentUser.isAdmin` 时显示；后端权限校验是最终边界，普通用户直接请求管理接口返回 `403`。

## 验证

- JDK 17 下 `mvn package` 通过，2 个已有工具单测通过。
- MyBatis-Plus 3.5.12 在 Spring Boot 3.5.16 下启动成功，6 个 Mapper XML 加载并连接真实 MySQL/Redis。
- MyBatis-Plus 接口回归通过：注册 `201`、登录与 `/me` 正常、会话列表正常、普通用户管理接口 `403`。
- 前端 `npm run build` 通过。
- 普通用户：注册 `201`、登录响应 `isAdmin=false`、会话接口 `200`、管理总览 `403`。
- 临时管理员：登录响应 `isAdmin=true`，总览、会话分页、工具统计、会话详情和普通会话接口均验证成功。
- 本地浏览器视觉检查因应用安全策略拒绝访问 `127.0.0.1`，未完成截图检查；不影响上述构建和 API 验证。
