# 2026-08-22：Agent 配方运行参数与工具白名单

## 背景

事件插件与 Agent 配方迁移完成后，`agent_config` 已经可以配置系统提示词和启用插件，但 AgentLoop 的循环限制仍全部来自 `application.yml`，不同 Agent 实际上不能使用不同的运行参数。

同时，工具注册表中的工具默认全部暴露给每个 Agent，无法通过 Agent 配方构建“无工具 Agent”或“只允许部分工具的 Agent”。

## 本次变更

- 新增 `agent_config.enabled_tools` 字段，独立表达 Agent 的工具白名单。
- `enabled_tools = NULL` 兼容旧数据，表示启用全部已注册工具。
- `enabled_tools = []` 表示显式禁用全部工具；非空数组只启用列出的工具。
- AgentLoop 构建模型请求时按工具白名单过滤 ToolCallback。
- ToolExecutor 执行入口再次校验工具白名单，避免模型或其他调用路径绕过限制。
- 新增 `AgentLoopConfig`，从 `magic_params.loop` 解析 Agent 级循环参数。
- 支持配置最大 Attempt 次数、工具循环轮数、单轮工具数、运行时长、退化重试次数和重复工具调用限制。
- `application.yml` 保留默认值和安全上限，数据库中的 Agent 配置只能在上限内覆盖。
- 旧数据库启动时自动补充 `enabled_tools` 字段，新安装 schema 同步更新。
- 设计文档补充 Agent 配方配置契约。

## 配置示例

```json
{
  "loop": {
    "maxAttempts": 2,
    "maxToolRounds": 6,
    "maxToolsPerRound": 2,
    "maxRunDurationSeconds": 60,
    "maxDegenerateRetries": 1,
    "maxSameToolSignature": 2
  }
}
```

工具配置示例：

```json
["current_time", "calculate"]
```

## 设计决策

- `magic_params` 继续作为 Agent 级扩展参数容器，当前先落地稳定且与 AgentLoop 直接相关的循环参数。
- 工具能力不放入 `magic_params`，使用独立的 `enabled_tools` 字段，便于查询、展示、校验和未来做权限控制。
- YAML 不完全移除：它承担全局默认值和安全上限；数据库承担 Agent 间差异化配置。
- 每次提交前，解析后的有效配置会固定到 `AgentExecutionContext`，保证异步执行期间不会因配置变化而漂移。
- 当前仍不引入 Workflow；“无工具、单轮、特殊提示词、不同插件”等场景先通过 AgentLoop 配方完成。

## 验证

- 使用 JDK 17 执行 `mvn clean test`。
- 共 8 个测试通过，新增测试覆盖：
  - `magic_params.loop` 按 Agent 解析；
  - 超过 YAML 安全上限时裁剪；
  - 旧 Agent 全量工具兼容；
  - 工具白名单；
  - 显式空工具列表。
