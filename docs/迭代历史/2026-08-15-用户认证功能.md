# 用户认证功能

> 日期：2026-08-15
> 阶段：M3 用户体系基础

## 目标

为 AI Agent 增加最小可用的用户体系：用户可以注册、登录、退出登录；业务接口默认要求登录；页面刷新后可以恢复登录状态并显示当前用户名。

## 实现内容

### 后端

- 使用 `app_user` 表保存用户信息：自增 ID、唯一用户名、BCrypt 密码哈希、状态和时间字段。
- 使用 JDBC + `JdbcTemplate` 访问用户表，暂不引入 ORM。
- 新增接口：
  - `POST /api/auth/register`
  - `POST /api/auth/login`
  - `POST /api/auth/logout`
  - `GET /api/auth/me`
- 使用 Spring Security 保护接口，默认要求认证，仅放行注册、登录、CSRF 初始化和 `/api/ping`。
- 使用 Spring Session Data Redis 保存服务端 Session，Session 默认有效期为 7 天。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；生产环境可通过 `COOKIE_SECURE=true` 开启 `Secure`。
- 为 Cookie Session 保留 CSRF 防护，前端通过 `XSRF-TOKEN` Cookie 和 `X-XSRF-TOKEN` 请求头完成请求校验。
- 使用 `schema.sql` 幂等创建用户表，同时更新 Docker MySQL 首次初始化脚本，兼容已有数据卷。

### 前端

- 增加登录和注册模式切换。
- 注册成功后回到登录模式，不自动登录。
- 页面初始化调用 `/api/auth/me`，根据响应恢复登录状态。
- 登录后在聊天页右上角显示用户名，并提供退出按钮。
- 业务请求统一携带浏览器 Cookie；收到 `401` 时清理前端登录状态并返回登录界面。

## 验证记录

- MySQL 8.4 容器健康，端口为 `127.0.0.1:3306`。
- Redis 7 容器健康，端口为 `127.0.0.1:6379`。
- 前端 `npm run build` 通过。
- 后端使用 JDK 17 执行 Maven 构建，编译和打包通过。
- 注册接口实际返回 `201`。
- 登录接口实际返回当前用户名，说明用户查询、密码校验和 Session 创建链路已跑通。
- 首次联调发现 `AuthenticatedUser` 未实现 `Serializable`，导致 Redis Session 保存时返回 `500`；已补充 `Serializable` 修复。
