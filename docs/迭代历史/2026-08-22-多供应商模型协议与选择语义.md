# 多供应商模型协议与选择语义

## 背景

本轮需要同时支持 Agent 切换、模型切换以及不同供应商的 OpenAI 兼容协议。模型供应商、模型名称和请求协议不是同一个概念，不能用供应商品牌推断协议，也不能把所有供应商都固定到 Spring AI 的单一默认连接。

## 设计决策

- `model_provider_config` 保存供应商连接、模型目录、协议类型和通用 `endpoint_path`；API Key 支持数据库值或 `env:变量名` 引用。
- `ModelProtocolRegistry` 根据 `protocol_type` 发现适配器。当前支持 `OPENAI_CHAT_COMPLETIONS` 和 `OPENAI_RESPONSES`。
- Chat Completions 使用 Spring AI 的工具调用模型；Responses 使用原始 JSON 请求，保留 typed output item，并将 `function_call` 与 `function_call_output` 转换为 AgentLoop 的统一消息。
- 每个 Turn 提交时捕获完整模型配置，运行中的 Turn 不受会话后续选择影响；选择变化从下一 Turn 生效。

## 前端选择语义

前端保持 Agent 和模型两个选择框，不增加“跟随 Agent 默认模型”选项：

| 操作 | 实际执行配置 |
| --- | --- |
| 新会话什么都不改 | `general` + general 默认模型 |
| 只选择 Agent | 新 Agent + 新 Agent 默认模型 |
| 只选择模型 | 当前 Agent + 指定模型；新会话按 `general` 处理 |
| 同时选择 Agent 和模型 | 指定 Agent + 指定模型 |
| 已有会话什么都不改 | 沿用会话当前配置 |
| 已有会话切换 Agent | 自动切换到新 Agent 默认模型 |

## 验证

- 后端单元测试覆盖协议注册、Responses output item 回放、工具调用配对和 usage 解析。
- 前端构建通过，后端测试与打包通过。
- GLM 的 CC Switch 配置已校正为 `OPENAI_CHAT_COMPLETIONS` 与 `/chat/completions`；proaiapi 和呆呆兽继续使用 `OPENAI_RESPONSES` 与 `/responses`。

## 安全边界

API Key 不返回前端、不写入源码或文档、不进入日志和异常信息。用户自定义供应商正式开放前，还需要增加加密存储、所有权校验和凭据管理接口。
