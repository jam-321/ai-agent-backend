# 模型故障转移与执行健壮性

- 日期：2026-08-24
- 分支：`feature/model-failover-resilience`

## 背景

原有 OuterLoop 只会使用同一个模型重试，模型供应商连接超时或临时过载时，重试无法改变故障来源。本轮补充 Agent 级备用模型路由，并让模型错误分类、Attempt、实际模型记录和上下文检查点保持一致。

## 本轮改动

- `agent_config` 增加可选 `fallback_model_provider_key` 和 `fallback_model_name`。
- 管理端 Agent 配置增加降级模型供应商和模型选择；未配置时保持原有同模型重试行为。
- 新增 `ModelFailureCategory`，按网络错误、HTTP 状态码和错误关键词区分超时、限流、过载、鉴权、模型不存在、格式错误、计费和上下文超限。
- 只有临时性故障进入模型降级；鉴权和请求格式错误直接终止，不重复浪费请求。
- `AttemptRunner` 每个 Attempt 固定一个模型；备用模型成功后，最终 assistant Turn 记录实际成功模型。
- Chat Completions 和 Responses 适配器的连接/读取超时改为配置项，默认读取超时 45 秒。
- 上下文摘要先保存到当前 Turn 内存检查点，Turn 成功后再落库，避免失败 Attempt 的摘要污染下一轮历史。

## 验证

- JDK 17 下 Maven 测试：38 项全部通过。
- 前端生产构建通过。
- 使用不可连接的临时主供应商进行真实接口验证：主模型连接被拒绝后分类为 `TIMEOUT`，OuterLoop 切换到 `deepseek-v4-flash`，Turn 最终 `COMPLETE`。
- 临时供应商和测试路由已恢复/删除，现有测试 Agent 恢复为默认 DeepSeek 且未配置备用模型。

## 暂不包含

- 熔断器和多实例共享的模型池状态。
- Tool 执行超时与取消机制。
- 不支持图片模型的视觉转文字降级。
