### 扩展架构与模型

- 后端按功能模块组织：`agent`、`auth`、`conversation`、`monitoring`、`workflow`、`common`。
- Agent 通过 `agent_config` 配置系统提示词、工具、插件、运行参数、默认模型和执行类型。
- AgentLoop 和 Workflow 通过统一执行器注册表路由；事件插件由 Dispatcher/Registry 发现和分发。
- `model_provider_config` 支持多供应商、模型目录、协议、Base URL、API Key 和模型能力元数据。
- 会话可在不同 Turn 切换 Agent 和模型；每个 Turn 保存实际使用的 Agent、模型和协议。

### 管理与监控

- 管理员可查看运行总览、全部用户会话、Turn/Node 详情、工具统计、用户、Agent、供应商和操作审计。
- 普通用户只能访问自己的会话和数据；管理员接口由权限规则保护。
- 后端持久化已统一迁移到 MyBatis-Plus，历史数据库通过幂等启动迁移补齐结构。
- 管理端已引入 Element Plus，Agent 与供应商配置改为结构化表单并保留实时 JSON 预览；Tool、插件、协议和 Workflow 选项来自后端运行时 Registry。

### 多模态图片能力

- 图片使用 MinIO 保存，MySQL 保存 `media_asset` 元数据和 `conversation_turn_attachment` 关联，不持久化 Base64。
- 支持 JPEG、PNG、GIF、WebP；图片必须和文字一起发送，单张最大 20MB，单个 Turn 最多 5 张。
- `/api/chat` 统一使用一个 `multipart/form-data` 接口，图片字段可选；前端支持文件选择、缩略图、删除和直接粘贴截图。
- 模型能力绑定在模型目录的 `supportsImageInput` 元数据上；不支持视觉的模型上传图片时拒绝执行。
- Agent 图片历史策略支持：
  - `FULL_IMAGE_HISTORY`：当前模型支持视觉时重建历史图片。
  - `SUMMARY_TOOL`：历史只保留文本，模型按需调用 `query_image_summary`。
- 内置 `general` Agent 当前默认使用 `FULL_IMAGE_HISTORY`；其他 Agent 默认仍为 `SUMMARY_TOOL`。
- 图片 Turn 完成后异步生成摘要并保存为图片元数据和执行节点；摘要失败不影响主回答。

### Token 预算与上下文压缩

- 每次模型调用写入成对的 `MODEL_CALL` 节点，结构化记录输入、输出、缓存、推理、总 Token、耗时和 usage 来源。
- Chat Completions 直接解析供应商原始 usage，优先支持 DeepSeek 缓存命中/未命中 Token，并兼容标准 OpenAI 和常见中转字段。
- Agent 通过 `magic_params.budget` 配置 Turn 累计预算、上下文上限、最大输出和单次用户输入上限，YAML 保留全局默认/安全上限；LOOP 与 WORKFLOW 共用同一预算追踪器。
- Agent 通过 `magic_params.memory.maxToolPairsPerTurn` 独立控制历史重建时每个 Turn 回填的工具调用对数量，默认值为 3。
- 上下文采用两层保护：Tool Result 本地截断，以及当前 Turn 工具结果回填后触发的大模型上下文压缩。压缩结果作为 UserMessage 检查点持久化，保留最近约 30000 Token；不再在 Turn 开始单独压缩。
- 管理员大盘、全部会话和 Turn 执行树展示模型调用次数、Token 聚合和缓存命中率；供应商未上报缓存数据时明确显示“未上报”。

### 模型容灾与执行健壮性

- Agent 支持可选的备用模型配置；主模型发生超时、限流、过载或模型不存在时，OuterLoop 可切换备用模型，下一 Turn 仍优先主模型。
- 模型调用超时可通过 `agent.model.connect-timeout` 和 `agent.model.read-timeout` 配置，错误事件记录分类和实际使用模型。
- 上下文压缩检查点在 Turn 成功后才持久化，失败 Attempt 不会污染后续历史。
