# 主线 1：未来规划（游戏开发导向）

> 更新：2026-08-25
> 方向：把 Agent 用于**游戏场景**。原"通用 Agent 框架四阶段"已降为**远期参考**（见文末），不再是当前主线。

## 主线目标

做这个 Agent 的目的就是**用于游戏场景**——让它作为游戏里的"**角色灵魂层**"：NPC / 看板娘等角色拥有独立意志、记忆、关系，能做真正意义上的互动。与主线 3 探索的「游戏 + Agent」方向一致：**表里双世界 + 关系驱动 agent RPG**。

- **表世界**：看板娘（了解游戏、能聊三次元）、momotalk（能和里世界好友聊天）、外世界 Home 菜单。
- **里世界**：进入二次元故事。第一章《寻找小光》（致敬兰斯）——复刻兰斯 1 的**卡牌地牢探索 + 回合战斗 + 收集养成**。

## 当前基线（可复用）

后端 Agent 层基础已具备：登录 / 会话持久化 / 跨轮短期记忆 / Tool Calling / 插件事件流 / 多模型 / 管理员监控 / 多模态图片 / Token 预算压缩 / 模型容灾，并扩展出 Workflow 执行类型。前端 Vue3 + Vite（初版，技术栈未定）。

**待扩展（游戏落地关键缺口）**：**长期记忆、Skill 系统**。

## 近期要做（开发游戏）

### 1. Agent 能力扩展（游戏所需的智能）
- **长期记忆**：跨会话记住玩家/角色关系、剧情进度、收集物、好感度；支持"游戏内 / 外"延续。
- **Skill 系统**：角色能力 tool 化——
  - 确认加好友（回外部世界还能聊天）
  - 跟随（与主角同行）
  - 战斗能力（不同角色战力 / 技能不同）
  - 通用 RAG 搜索知识 / 记忆
- **自由文本 → tool 映射**：玩家手动输入能稳定映射到角色 tool / 决策。
- **记忆一致性**：多角色、多会话共享"世界状态"，保持不 OOC。
- **成本控制**：token 按游玩可控（先免费内测，再评估收费）。

### 2. 与前端 / 引擎整合（游戏场景）
- **引擎与内容分离**：代码只写引擎，剧情 / 战斗 / 地点 / 角色做成数据（JSON）注入。
- **剧情（galgame）**：分支文本、立绘、选择肢、存档、backlog、skip/auto。
- **地图**：里世界地图（利萨斯城 5 地点卡：学校 / 街角 / 旧书店 / 公园 / 警局），点卡进剧情。
- **回合战斗**：兰斯式（筹码 / 冷却），作为剧情推进器。
- **表世界**：看板娘 + momotalk 图标 + 外世界 Home。

### 3. 技术栈落地
- 前端：Vue3 + Vite（已有初版）+ 渲染层 **PixiJS**（卡牌 / 战斗 / 立绘动画）+ Tailwind（样式）；技术栈待定，先用现有 Vue3 验证。
- 通讯：前端 → 后端 agent 用 **WebSocket / SSE**（流式），传游戏状态上下文，接收流式文本 / 行为指令。
- 后端：沿用现有 Spring Boot 3.5 agent 层，扩展长期记忆 / skill 注册表。

### 4. 上线（M4）
- 云服务器 + Nginx 反向代理 + HTTPS 域名。
- 游戏内测（自己先玩通：登录 → 打一场战斗 → 跟 agent 角色说上几句，觉得"有点意思"）。
- 系统化自动测试 + 数据库与监控页对照。
